## Goal

Prove that Prism doesn't crash, doesn't glitch the lights and doesn't lose work, and make it
effortless for a non-lighting person to learn.
- You find the bugs; owners fix them. Fix trivial ones yourself; report the rest to the
  orchestrator with exact repro steps.
- You write the docs a new user actually reads.

## You own

`Tests/PrismCoreTests/Fuzz*Tests.swift`, `Tests/PrismCoreTests/Journey*Tests.swift`,
`Tests/PrismAppTests/Journey*Tests.swift`, `tools/qa/**` (new), `README.md`,

screenshots), and `.github/workflows/nightly.yml` (coordinate edits to `ci.yml` with the
orchestrator).

## Deliverables (priority order)

### 1. Fuzz and robustness tests (Linux, deterministic seeds)

Every external input must survive garbage without crashing or hanging. Each fuzz target runs
thousands of seeded cases on Linux in under 30 s.
- **Project files** (`ProjectIO`):
  - truncated, bit-flipped, wrong types, huge arrays, NaN/∞ numbers, future versions,
    duplicate IDs;
  - each case either opens (repaired) or fails with a friendly error, never a crash.
- `.lightkeyproj` import, fixture JSON/OFL/QLC+ import, and `.prismlook`.
- Remote/WebSocket messages and OSC packets (with the remote and integrations teams' parsers).
- Enttec serial response parsing (with the hardware team): partial frames, wrong labels,
  oversize lengths.
- Assistant text input: very long, emoji, mixed languages, injection-like strings.

### 2. Soak and stress (nightly)

- `Prism --soak <minutes>` (engine team) in `nightly.yml`.
- The soak exercises:
  - random look recalls;
  - effects;
  - music mode on synthetic audio;
  - remote commands;
  - undo/redo;
  - hot-plugging a simulated interface.
- **Assert:**
  - no crash;
  - RSS growth < 20 MB per hour after warm-up;
  - frame p99 within budget;
  - no output gaps over 100 ms.
- Upload a small CSV and a chart.

### 3. End-to-end journeys

Headless, through public APIs. They run in `swift test` and as `--self-test` checks:
1. **New user:** demo studio → recall "Chill Vibes 4" → DMX matches the golden bytes.
2. **Patch:**
   - add a light with the wizard API (PT4c, 8-pixel mode);
   - auto-address with no overlaps;
   - unpatch;
   - undo restores it.
3. **Precise colour:**
   - set `#14D8F0` on a tube;
   - verify it round-trips through the inspector model;
   - verify the DMX bytes;
   - Kelvin + tint on the panel.
4. **Save, reopen, share:**
   - save the project, quit, reopen: identical;
   - export a `.prism` bundle → import on a "second machine" (temp dir) → identical.
5. **Crash safety:** kill mid-save (simulate) → reopen → the last good version or a backup is
   offered, never a corrupt file.
6. **Music mode:** synthetic 120 BPM audio for 60 s → beat lock, no frame with a flash above the
   safety rules, smooth palette changes.
7. **Guest remote:**
   - pair as guest;
   - try a strobe, a 0-s fade, protected key light, out-of-range intensity → all refused or
     clamped;
   - the kill switch revokes the session.
8. **Voice/assistant:** "warm up the background a bit, bring the fill down a little" → the
   expected relative changes on the right fixtures.

### 4. Release confidence

- Check the install-test job (`ci.yml`) stays green.
- Add a "fresh Mac" check: first launch with no Application Support folder, then onboarding.
- **Launch time:** process start → first rendered frame. Target < 1.5 s on CI (report the
  trend).
- Memory with the full fixture library indexed.
- Bundle size; flag anything above 80 MB.

### 5. Docs for humans

Plain English, short sections, screenshots from the CI tour (copy the best ones to
`docs/images/`, < 300 KB each, PNG or JPEG).
- **`README.md`:**
  - what Prism is (one hero screenshot);
  - install one-liner;
  - feature tour;
  - "Your first 5 minutes";
  - supported hardware;
  - building from source;
  - license and third-party notices.
- **`docs/USER_GUIDE.md`:**
  - plugging in the Enttec;
  - adding lights (wizard), "Which light is which?" (Light Finder);
  - stage and inspector (hex, Kelvin, tint);
  - looks and folders;
  - Live page;
  - music mode (system audio permission);
  - talking to Prism;
  - phone remote and share links (and what guests can't do);
  - importing from Lightkey;
  - sharing project files;
  - keyboard shortcuts;
  - glossary (DMX, universe, address, mode — explained gently).
- **`docs/TROUBLESHOOTING.md`:**
  - interface not detected;
  - lights not responding or flickering;
  - wrong colours (mode mismatch);
  - permissions (microphone, camera, system audio, local network, speech);
  - the remote won't connect;
  - resetting safely.
- **`CHANGELOG.md`**, generated from merged work (user-facing wording).

### 6. Audits (report to the orchestrator; fix trivial issues)

- **Accessibility:** VoiceOver labels, keyboard navigation, contrast, Reduced Motion.
- **Copy:** jargon without explanation, inconsistent names (light vs fixture), typos.
- **Visual:** clipped text, misalignment, empty states, in every tour screenshot.
- **Concurrency:** go through nightly sanitizer reports and route them to owners.

## Acceptance

- Fuzz suites green on Linux.
- The nightly workflow runs soak + sanitizers, with uploaded results.
- Journeys 1–8 pass in CI (journeys that depend on unfinished features can be `XCTSkip`ped with
  a reason, then enabled as features land).
- README, user guide and troubleshooting docs are complete, accurate to the shipped app, and
  have screenshots.
